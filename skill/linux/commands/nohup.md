# nohup · 起一个后台常驻的命令

**用途**：让一条命令**脱离终端在后台跑**（终端关了、这次对话结束了它还在）。起临时服务、跑长任务用这个，不要直接跑（前台跑会占住，一超时就被掐）。

**用法**：nohup 命令 [参数]... **&**（末尾这个 `&` 必须有）

**常用选项**
- 只有 `--help` / `--version`；真正的开关是 shell 的 `&`

**示例**
- `nohup python -m http.server 8899 > logs/http8899.log 2>&1 &`　起个临时 HTTP 服务，输出写进日志
- `nohup ./run.sh > /tmp/run.log 2>&1 &`　起个脚本
- `ss -ltnp | grep 8899`　**起完必须复查**：确认端口真在听、进程名和 pid 对
- `kill 12345`　停掉它（pid 从上面那条 `ss` 拿）

**备注**：三个要点 —— ①末尾 `&` 不能少（少了就是前台跑，会把这一轮卡到超时）；②**输出要重定向**（`> 日志 2>&1`），不然它的输出会跟着终端走；③程序见到末尾带 `&` 的命令会**立刻返回 pid 并把输出另存一份**（`logs/exec/<时间>-bg.out`），所以"起服务"这种活不会白等 —— 但也就不会替我们等它起来，**起来没起来必须自己再查一次**（`ss -ltnp | grep 端口`）。要停的时候用 `kill <pid>`，别用 `pkill -f` 乱匹配。
