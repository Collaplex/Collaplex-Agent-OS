## 什么时候用

**该用**：
- 问题涉及**自己以前存过的资料、项目细节、历史记录** —— 不是通用常识
- 你不确定"这个我到底是知道还是不知道"
- 需要**原文出处**

**不该用**：
- 通用常识、数学、闲聊
- 通用知识（怎么写代码、什么是梯度下降）
- 上下文里已经有答案了

## 怎么调

```bash
.venv/bin/python skill/rag/main.py recall "查询文本" -n 5 --json
```

| 参数 | 说明 |
|---|---|
| `-n` | 返回条数，默认 5 |
| `--json` | 结构化输出，**建议加** |
| `--tier 2\|3` | 只查某一层（一般不用管） |

不给查询直接跑会进交互模式，`/exit` 退出。

## 返回什么

```json
{
  "query": "黑洞蒸发是怎么回事",
  "hit": true,
  "threshold": 0.53,
  "results": [
    {
      "rank": 1,
      "score": 0.6414,
      "index": 1,
      "hash": "a5e3ba3d1286125a",
      "source": "diagrams/summary.md",
      "text": "## 黑洞蒸发与霍金辐射\n\n霍金辐射是黑洞因量子效应向外辐射粒子……"
    }
  ]
}
```

- `hit: true` → `results` 是命中的原文片段，**按相似度降序**
- `hit: false` → `results` 是空数组，**这就是真没检索到**
- `text` 是**原文，完整不截断**；`score` 是 0~1 余弦相似度
- `source` 是这段原文出自哪个文件

## 边界

- **只读** —— 不写任何数据，别指望它能记住东西。写库是管线的事，不是它的事
- **不做推理、不做总结** —— 原文原样交给你，怎么用是你的判断
- **`hit: false` 不要硬编** —— 如实说没查到，别拿常识顶上
- **原文照用** —— 别改写、别润色，改了就不可追溯
- 低于阈值（默认 `0.53`）视为没命中；阈值在 `resources/embed.json` 的 `hit_threshold`

## 出错了怎么办

| 症状 | 处理 |
|---|---|
| 连不上向量服务 | `.venv/bin/python skill/rag/scripts/embed_server.sh start` |
| 索引不存在 | 先建库，见 `README.md` |
| 维度不一致报错 | 换过向量模型，索引要重建 |


## 清洗管线（热层 -> 历史对话 + 经验层）

`scripts/refine.py` —— 热层(tier=2)那场聊完了，往下沉。

**目标形态**（2026-10-08 rag更新.drawio 定的新架构）：

1. **原文进历史对话** —— tier=1 `kind='对话'`，带 `对话id`/`对话时间`，**永久留**（可回溯）
2. **提炼进经验层** —— 概述 / 知识 -> tier=3（别名进 `alias.json`，不嵌向量），
   每条挂 `来源id` 指回它出处的 tier=1 行
3. **清空热层** —— tier=2 的那批对话产出清掉（原文已在 tier=1 躺好才敢清）

★ **代码现状（2026-10-08）**：`refine.py` 里的 tier 常量还是老的两层写法（2->3 搬 `kind='原文'`），
**尚未改成上面的三步**；老数据已由 `scripts/落地历史对话层.py` 一次性归位（tier=3 的 `kind='原文'` 已下沉到 tier=1）。
改 `refine.py` 时照本节的三步来，别再把"原文"留在经验层。

**老写法的三条（存档，别照抄）**：
1. 先复制 —— 二层切片原样搬进三层（标 `kind="原文"`，向量复用不重算）
2. 再清洗 —— 按 source 读回 `corpus/` 原文，跑三遍小模型出 概述/知识/别名
3. 清空二层 —— 只清刚清过的那批对话产出

★ **触发**：主 agent 把 seek skill 的 `任务结束` 键落进 `state/activity.json`
（**收到提问**写 false、**答完**写模型给的那个 —— 中间那段也在计时内）。
清洗的 `--看守` 按三条判据动手：

1. 静默 ≥ **20 分钟**（`refine.idle_seconds`）
2. 任务结束 = true，**或者**静默 ≥ **2 小时**（`refine.hard_idle_seconds`，兜底：
   管"模型判没办完、人却再没回来"，没这条二层会一直积着）
3. 这之后没清过（少了它，自动触发就变成每分钟把同一批重新喂模型）

★ **收到提问时就按住计时**：否则上一轮答完快满 20 分钟时，用户刚提问、模型还在想，
看守会趁这个缝把二层清掉。

★ **提示词**在 `config/skills/refine-{summary,knowledge,alias}.md`，
文件名登记在 `config/agent.json` 的 `refine.prompts`（代码里不写死）。

| 跑法 | 干什么 |
|---|---|
| `refine.py` | 立刻清一次 |
| `refine.py --看守` | 常驻，到点自己清 |
| `refine.py --干跑` | 只看要清什么，不动库 |
| `refine.py --安静` | 没活干不出声 |

## 别名路（检索的第二路）

清洗管线产出的 `scripts/alias.json` 接进了检索：

- `search.py` 的 `load_aliases()` / `expand_query()` / `search_with_alias()`
- `recall.py` 每层都用它（`search()` 本身**不动** —— 它是纯函数，别名路包在它外面）

**怎么走**：查询里**字符串包含**某个概念 → 把该概念的别名池各检索一遍 → 按 index 合并去重保留最高分。
别名表**不嵌向量**，所以这条路几乎不花算力。

**为什么需要**：用户问「网络设备」，语料里答的是「软路由 / 交换机」—— 机器自己看不出这层对应。

实测（同一条查询，控制变量）：

| | top1 | 判定 |
|---|---|---|
| 关别名 | 0.5178 | 未命中 |
| 开别名 | 0.8163 | 命中 |

参数在 `resources/embed.json` 的 `alias` 段（`enabled` / `base_k` / `max_aliases` / `per_alias`）。

★ **进表前过 `alias_acceptable()`**：**单字**（`库`/`冷`）和**包含关系**（`库` ⊂ `二层热库`）一律不收。
模型会产这种（实测 8 组里 6 组是），而单字别名会让**任何含这个字的查询**都多跑一遍 ——
别名路本为提召回，这么搞反降精度。提示词里写规矩不管用，只能程序拦。


## 三层记忆架构（2026-10-08 落地 rag更新.drawio）

表是**一张** `rag_chunks`，用 `tier` 分层。编号越大越"熟"：

| tier | 层 | 装什么 | 现状 |
|---|---|---|---|
| **1** | **历史对话**（底档）| `kind='对话'` = 所有场次的原文，**带 `对话id` + `对话时间`（= 时间线）**；`kind='文件'` = 文件切片 | 1,789 对话（559 会话）+ 1,052 切片 |
| **2** | **热层** | 当前这场会话的活记忆 | 空（跑起来才有）|
| **3** | **经验层**（原冷层）| 提炼出的 `概述` / `知识` | 125 条 |

**流向**：模型上下文窗口 → 热层(2) → 沉下去，原文进历史对话(1)、结论进经验层(3)。

### 指针：经验 → 原文

`tier=3` 每行的 `来源id` 列 = 它出处 `tier=1` 那些行的 id（逗号分隔）。
经验是从**文件**提炼的，所以按 `source`（文件路径）匹配，不是按文本。

```sql
-- 顺指针回溯
select text from rag_chunks where id = any(string_to_array('14965,14967', ',')::bigint[]);
```
