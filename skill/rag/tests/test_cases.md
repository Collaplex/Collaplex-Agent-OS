# rag 检索质量回归用例

## 这组用例是干嘛的

回答一个问题：**改完切片 / 换完模型 / 加完语料，检索还是不是原来那个水平？**

用例来自命中阈值标定时用的 12 条探针：6 条**该命中**（二层库里确实有），
6 条**该不命中**（通用常识，库里没有）。跑一遍就知道有没有退化。

## 怎么跑

```bash
# 1. 起向量服务
.venv/bin/python skill/rag/scripts/embed_server.sh start

# 2. 逐条对 eval.yaml 里的查询跑一遍, 看 hit 跟 expect 是否一致
.venv/bin/python skill/rag/main.py recall "<query>" -n 1 --json
```

## 判定标准

| 检查项 | 通过条件 |
|---|---|
| **命中判断** | `hit` 跟 `expect` 一致（这是硬指标） |
| **层级** | 命中时 `tier` 跟 `tier` 一致 |
| **出处** | 命中时 `source` 跟 `top_source` 一致（命中了但不是那个文件 = 语料有噪声） |
| **分数** | `score` 不低于 `baseline` 太多（下跌 > 0.05 要查原因） |

`baseline` 是 2026-10-05 在 375 条二层库上的实测值，**只是参照，不是硬阈值** ——
语料一变基线就变，重点看趋势。

## 已知的薄弱处

**阈值两侧余量只有 ±0.03**：相关最低 0.5599，无关最高 0.4983。样本只有 12 条，
换模型或语料规模大变之后，`hit_threshold` 必须重新标定。做法见 `eval.yaml` 里的注释。

## 语料里不能放的东西

**查询词原样出现在语料里 = 必然命中**。这条踩过：`examples/` 和 `tests/` 里的样例输出
含查询原句，被索进语料后每次都以 0.76~0.82 霸榜，问什么都先命中它自己。
两个目录已加进 `exclude_dirs`。加语料时同理：别把"问题清单 / FAQ 问句"直接当语料灌进去。
