# 语料 · 看库里有什么、还剩几次、过期怎么清

**用途**：摸清搜索语料库的现状（两表多大、哪来的、热窗口里有多少、本轮还能搜几次），
以及手动跑 TTL（下沉 / 清理）。

**用法**
- `.venv/bin/python skill/search/main.py 语料 [--json]`　总览
- `.venv/bin/python skill/search/main.py 过期`　把过期的热行沉到冷库
- `.venv/bin/python skill/search/main.py 清理 [--dry]`　冷库到点/超量的删掉，截图跟着一起清

**两表是什么**
- `search_hot` **热库**：刚搜到的结果条目与页面切片，**检索只查这张**；过了热窗口（默认 24h）沉冷
- `search_corpus` **冷库**：沉下来的原件（默认 90 天 / 2GB 封顶），不参与检索，只做复用

**示例**
- `语料`　看行数 / 大小 / 来源分布（bing 10、百度 7）/ 本轮闸 `已用 1/100`
- `清理 --dry`　先只数不删，看清要清多少

**备注**
- **TTL 平时不用手动跑**：每次 `搜` 或 `正文 --save` 落库时都会顺手做一遍（沉冷 + 清冷 + 清截图），
  脚本会打 `[落库] … 顺手维护 沉冷库 N 热库清 M`。这两条命令是手动补跑用的。
- **截图跟 TTL 一起清**：页面块落库时记了截图路径（`取` 与 `正文` 的落盘用同一个指纹命名），
  所以冷库那行到点被删时，那张 jpg 一起删（老板定的）。删完还会扫一遍"没人引的孤儿截图"。
- **单轮 100 次闸**：一轮 = 连续动作间隔不超过 30 分钟的一段；到上限 `搜` 会被直接拦下并说明原因。
  状态在 `cache/budget.json`。要调上限改 `resources/store.json` 的 `budget.max_per_round`。
- 库与 rag 同一个 PG 库（`RAG_PG_DSN`），但**表是独立的**，互不影响。
