# 解析结果页 · 拿存下来的结果页 HTML 离线解析（排障/复查用）

**用途**：`搜` 那一步**已经落盘的**结果页 HTML，再解析一遍 —— 不用出网、不扣次数。
两个真实用场：①这次搜出来「0 条」，想确认是**被挡了/改版了**还是**真没有**；
②同一批结果要换个查询词重排，不必再打一遍站。

**用法**：`.venv/bin/python skill/search/scripts/serp.py parse "<HTML文件>" [--site auto|bing|baidu] [--query "<词>"] [--json]`

（这条**不在 main.py 的动作表里**，直接叫实现件；`<HTML文件>` 从 `搜` 的 stderr 或
`skill/search/cache/pages/` 里拿 —— 落盘的页都在那，文件名带地址摘要。）

**选项**
- `--site auto` 哪家的页：`auto` 自动认（默认）/ `bing` / `baidu`
- `--query ""` 给了就用它重排（IDF 重排那一步）
- `--json` 出 JSON

**输出**：与 `搜` 同形的结果表（标题 / 链接 / 摘要 / 来源 / 名次）。

**备注**：①**认不出就是认不出**：页面里没有结果块（被挡的验证页、改版后的新 DOM）它会直说
「页面拿到了（N 字）但没解析出结果」，不会静默成「没搜到」—— 这也是查「到底是哪种 0 条」的正路。
②判「被挡」看有没有 `安全验证`/`captcha` 这些字样（`搜` 那条路里已经内置这句判断，这里是手动版）。
③离线解析**不再重排到最优**：`--query` 只做 IDF 重排，跟当时在线的对题率自检不是一回事。
