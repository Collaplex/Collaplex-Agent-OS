# 交叉验证（MTP）

## 任务目标

本地卡住 → 摇外援（`skill/outsource`）→ 外援回来还是不敢用 → **这一件**：
把同一题问**两家以上不同模型**，几份答案**并排**摆出来，再把**程序判得出的分歧点**挑出来，
一起当**参考资料**交给本地小模型，**让它自己综合**。

★ 这一件**不替调用方下结论** —— 它只负责"并排 + 挑分歧"；哪份对，由小模型（或主 agent）自己判。
★ 一次跑 = 2~3 次云端调用 → 比外援贵。**只在外援之后**用。

## 触发条件

**该用**：
- 外援的产出**用不了**（空答 / 跑挂 / 明显不对）
- 外援的答案和本地自己的答案**对不上**，谁也说不过谁
- 用户明确要求"多问几家 / 对比一下"

**不该用**：
- **还没摇过外援** → 先去摇外援
- 本地自己就能答（查资料 / 闲聊 / 格式转换）
- 只是想让答案"更权威" → 那不是交叉验证，是多花钱

## 怎么用

```bash
# 同一题问两家（默认 deepseek + mimo），出参考材料
.venv/bin/python skill/mtp/main.py ask "这段代码为什么死锁？<贴代码>"

# 指定哪几家 / 看状态
.venv/bin/python skill/mtp/main.py ask "<题>" --家 deepseek,mimo
.venv/bin/python skill/mtp/main.py status
```

## 输出

- **参考材料**（markdown）：题 / 参与的家 / 各家答案原文（带耗时）/ **程序判出来的对照**（哪些家一致、哪家是分歧）
- 落盘 `logs/mtp/<时间戳>-交叉验证.md`
- 记账：**跟外援共用一个流水** `logs/outsource/用量.jsonl`（每行带 `来自: mtp`）→ 钱只在一处看
- 退出码：0 至少两家答上 / 1 失败 / 2 没跑（开关关着或到预算）

## 边界与错误处理

| 情况 | 表现 | 怎么处理 |
|---|---|---|
| 配的少于两家 | 直接拒绝，退出码 1 | 交叉验证的本质就是两家以上 |
| 某一家答不上 | 那一份标 ✗ + 写清错误，其余照给 | 不因为一家挂了就整体失败 |
| 只有一家答上 | 材料照出，退出码 1 | 这时没用，别把它当交叉验证结果 |
| 没有任何两家一致 | 对照里逐条列分歧 | ★ **分歧本身就是价值**：别悄悄合并成一句话 |
| 开关关着 / 到预算 | 退出码 2，说明钱袋子原因 | 别绕（跟外援共用钱袋子） |

## 注意事项

1. **钱袋子沿用外援的**：家的凭据 / 价目 / 预算 / 记账全在 `skill/outsource/resources/outsource.json`
   —— 改一处，两边同时变（也能一眼看出"今天摇人花了多少"）。
2. **不替调用方下结论**：并排 + 挑分歧就到此为止。
3. **答案指纹靠末行约定**：系统提示词要求各家最后一行写 `答案: ...`，程序据此判一致/分歧；
   不守约就退化成"抠整段最后一个数字"。
4. **别升级成默认**：它是二级手段 —— 外援能解决的，不用它。
