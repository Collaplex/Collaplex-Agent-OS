# 一轮对话怎么走 · 内部分工

**用途**：搞清"用户问一句话，系统里发生了什么"，排错时才知道该看哪一段。

**链路（命令行与网页同一条）**
1. **提问** → 界面只留一条 `===` 和 `>`
2. **拦截层（子 agent）**：分析（要查哪些记忆）→ 判断（缺不缺 skill）→ 检索记忆 → 挑 skill → **按标准拼一份 skill 文本**（权限 / 位置 / 窗口预算：总窗口 × 40% − 输出预留 − 只读区）
3. **注入**：① 命中的记忆条目 ② 本次会话**最近几轮原文**（指代靠它）③ **命令库条目**（程序先替 exec 查好）
4. **主模型**流式出正文，末尾带唯一标记块（json 围栏）；思考开不开由**思考路由**定（硬规则 → 子 agent 判 → 默认关）
5. **左链要动手就派 exec**：声明 → 真跑命令（黑名单 + 宽目标 + 复读掐断）→ 产出落 `logs/exec/` → 入二层库
6. **收尾兜底**：整段回答被 json 围栏吃掉时 `捞正文()` 捞回来；**任何情况下不许让一轮问答静默消失**
7. 外援/交叉验证只在"本地卡住"时由程序判据触发（默认关）

**三个角色**
- `main.py`　主 agent（对话 + 决策 + 流式渲染）
- `sub_agent.py`　备料（分析 / 判断 / 检索记忆 / 拼 skill / 路由思考）
- `exec_agent.py`　执行（只干"要落在这台机器上"的活，动手过程全程可见）

**判据**：exec **真跑过**看日志里 `[exec agent] 跑：` 那几行 —— 那是"有没有真动手"的硬判据（入二层库也卡这条）；答得漂亮但一行没跑 = 演，不许入库。
