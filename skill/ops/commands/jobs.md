# 长活后台作业 · 起活 / 等跑完 / 取结果

**用途**：延时让写好的脚本或命令**跑到后台去跑**，回头再看它跑完没有、把退出码和日志尾收回来（`jobs.py`，就是项目根那个）。老板的规矩：**长活一律 setsid 起，绝不挂在对话进程下**（会话一关就没了）。

**用法（在项目里调）**
- `id = 作业.起(["python", "skill/rag/scripts/refine.py", "--强制"], 说明="重洗语料")`
- `作业.查(id)` → `{"状态": "在跑"|"跑完"|"失败", "退出码": int|None, "日志尾": str}`
- `作业.等(id, 每秒=回调)` → 等到它结束才返回，每秒回调一次读秒
- `作业.列()` → 这个项目起过的活

**落在哪**：账 `state/作业.json`，日志 `logs/作业-<id>.log` —— 都在项目目录里，**进程重启也读得回来**。

**备注**
- ★ 状态显示在网页的**「过程」里**（bridge 看护线程每 2 秒对账），不是底栏另开一栏。
- ★ 每轮开场的作业播报**只报「在跑」的**：上一轮甚至昨天就跑完的旧活不当新闻念（否则旧活每轮被念一遍、秒数是终值，看着像硬编码）。
- ★ 从命令行起长活时**别用前台 `&`**（终端工具会拦），正解是写一个 `.sh`：内部 `setsid nohup … &` 再 `echo pid=$!`，然后把这脚本前台跑 —— shell 一条命令就退，长活已脱离本会话。进度用 `tail -f` / 读日志，速率**实测两个时点相减**换算 ETA。
