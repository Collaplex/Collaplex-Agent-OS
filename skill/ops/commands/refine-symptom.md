# 清洗的症状与坑 · 看着像坏了的几种

**用途**：清洗是长跑，最容易被误判成"断了"。下面这几条是实测过的判据与真因。

**症状 → 怎么看**
- **"日志一动不动"** → 先分清哪一种：`refine.py` 自带行缓冲，输出是真·实时，所以 mtime 停住不是缓冲问题，而是它在跑"段数 × 3 遍"的请求、中间一行不出（已加每条请求一行进度）。判活看**日志增量**：隔 60 秒比字节/行数。
- **"心跳文件停了"** → `state/refine-心跳.json` 只在**整轮收尾**时写一次；积压一直在（每 10 分钟还在灌新语料）时一趟根本不收尾 ⇒ **心跳停在前一天是常态，不是卡死**。
- **"看着像断了，风扇也不响"** → 三条一起查：① `nvidia-smi` 0% ② CPU 98% idle ③ 主模型请求计数几乎不动（`grep -c print_timing logs/chat.log`）⇒ **算力压根不在本机**：`refine.read_env()` 自己解析 `.env`（环境变量覆盖不了），`.env` 指着云就走上云了。修法 = 用 `--本地`，**别改 `.env`**（那是老板配的、主 agent 在用），并连 cron 一起改成带 `--本地` 的版本。
- **历史对话层条数不涨** → 先翻日志有没有 `psycopg.errors.UniqueViolation: … rag_chunks_tier_hash_key`：同一段内容换个 `source` 名再来一次时，"按 source 先删后插"删不掉挂在别的 source 下的行 ⇒ 整轮崩退出（症状极像"没入库"）。修法 = `INSERT … ON CONFLICT (tier, hash) DO UPDATE`。
- **成片 `概述 0 / 知识 0` + `Connection refused` / 503** → 这轮是模型不在时起的，掐掉重来（掐它要按 pid **连子进程一起收**）。

**备注**：估工作量别拿 `--干跑` 报的"片"当模型调用数（片 = 二层行数）；真工作量单位 = **段**，调用数 = `Σ min(ceil(字符/12000), 12) × 3`。速率当场量两次，别照抄文档里的数。
