# 日志 · 哪件事该看哪份

**用途**：出问题先找对日志，别在错的文件里翻 —— ★ 这份说的是**这套系统自己**的日志（项目里 `logs/` 那一堆）；系统日志那类（`journalctl` / `dmesg` / 内核报错）去 `linux` skill。

**用法（都在项目根 `logs/` 下）**
- 一轮对话全过程：`logs/chat.log`（主 agent 与本轮前后发生了什么）
- 执行体真跑的命令与输出：`logs/exec/<时间戳>-NN.txt`（一轮几条命令几个文件）
- 清洗（热库 → 历史对话层 + 经验层）：`logs/refine.log`
- 灌二层/嵌入：`logs/embed.log`
- 网页那侧：`logs/web.log`
- 启动链进度（启动页那个框读的）：`logs/启动.log`
- 看门狗：`logs/watchdog.log`
- 外援记账：`logs/outsource/`；交叉验证：`logs/mtp/`
- 挑 skill 的留痕（问 / 检索词 / 候选分 / 挑中谁 / 声明）：`logs/挑技能.jsonl`

**用法（界面）**：设置页「日志」节按"谁产生的"分类，只读文件尾巴并自动刷；**文件不存在也列出来**（标"还没有"）。

**备注**
- ★ 长跑的日志**必须落在这里那几份上**（网页日志节读的就是它们）：别图省事重定向到 `/tmp` 或 scratch，否则老板会立刻说"web 里的清洗日志没动"。
- ★ 判"活还在动"看**日志增量**：隔一分钟比行数/字节数，别只比 mtime（大文件跑一段十几条请求中间一行不出，是常态）。
- 给长跑脚本重定向时，脚本自己**没设行缓冲**才要 `-u`；`refine.py` 自带行缓冲，不用加。
