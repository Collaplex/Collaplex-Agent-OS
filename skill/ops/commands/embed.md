# 灌二层嵌入 · 分批与重嵌

**用途**：把语料切片转向量灌进库（tier 2 热层 / 其他层），或改过切片器之后**全量重嵌**。

**用法**
- `./.venv/bin/python skill/rag/main.py embed <文件或目录...> --tier 2`
- 判进度**看库里条数**（不是看日志最后一行）：
  `psql -h /var/run/postgresql -U collaplex -d collaplex_rag -Atc "select tier, count(*) from rag_chunks group by tier order by tier"`
- 复用/待算看日志那行 `[增量] 复用 N 块, 待算 M 块` —— 按块哈希复用，**算 ETA 用"待算"别用总块数**（实测复用率 89%）

**备注**
- ★ **`embed.py` 是最后一次性落库，不是逐块落**：跑到 `464/650` 被停 ⇒ 库里仍是 0 条，**整批白算**。所以要停就等它跑完；全量**一律分批**（每批单独调一次），按**字节量**做 LPT 装桶切批（大的先排进当前最轻那组），别按文件数/行数切（语料大小差上百倍，会切出一个独占六成时间的巨批），切完打印每组 MB 核对。
- ★ 算 ETA 别拿开头小文件的速度估：小文件能到 3.9 块/s，一进 `hermes-history/` 大文件掉到 2~2.7 块/s。
- ★ 切片器/块文本一变，库里现存块全是改动前的产物 —— "还有哪些要重嵌"要按「块还是不是源文件的连续子串」重判（探针 `skill/rag/scripts/check-chunk-substring.py`），别信批次台账。全量重嵌**不用先清库**；但**重嵌期间清洗 cron 必须停着**（它第③步会删语料原文），顺序：先重嵌跑完 → 再挂清洗 cron。
- 落库前剔 NUL、超长块按 token 反推（中文 1 字 ≈ 1 token，窗口 8192 → 4000 字符），否则整批崩在最后一步。
