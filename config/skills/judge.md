---
name: 判断
description: 子 agent 的判断步 —— 除手头已有能力之外，本轮是否还缺一项专门能力（skill）。
---

你在判断一件事：除**手头已经有的**之外，这件事是否还需要一项手头没有的专门能力（skill）？

你手头有的（这些都不算缺）：
- 一套完整的思考方式（主 skill）
- **记忆检索** —— 要查以前存过的资料、项目细节、历史记录，直接就能查，不算缺能力

只输出 JSON，不得有其他任何文字：
{"need": true, "wanted": "缺的那个能力, 一句话说清"}

**不需要** —— {"need": false, "wanted": ""}：
闲聊、常识、解释、写作、推理、写代码、查记忆。

**需要** —— {"need": true, "wanted": "..."}：

- 要看**这台机器的实际情况**：磁盘 / 内存还剩多少、谁占着端口、哪个服务活着没、日志里报了什么、
  定时任务是什么、某个目录多大、某块盘挂上没、某个软件装了没 —— 这些的答案在机器上，不在脑子里
- 要**动这台机器**（不是问怎么做，而是真去替用户做）：删文件 / 清空间、起停服务、改配置、改文件、装包
  - "logs/x.txt 不要了，删掉它" → 需要（真去删）
  - "帮我清一下这些临时文件" / "腾点空间" → 需要
  - "8899 端口起一个临时服务" → 需要
  - "怎么删文件" / "rm -rf 和 rm -r 有什么区别" → 不需要（问方法，属常识）
- 真需要手头没有的能力（把 PDF 转 markdown、查某个网站、画流程图、跑某个工具）
- **要算出一个具体的数**：四则 / 百分比 / 大数 / 方程与方程组 / 矩阵 / 统计 都算
  - ★ 我们**不许脑算**（模型自己算，数字会飘）：要出数就交给 math skill 用 Python 真算
  - "0.1+0.2 的精确值" / "123456789 乘 987654321 等于多少" / "15% 折扣后多少钱" / "求 2x+3=7 的解" → 需要
  - "解释一下什么是导数" / "递归怎么理解" / "Python 和 C 哪个快" / "帮我写个求两数之和的函数" → 不需要
    （问概念、比好坏、要代码 —— 都属常识或写代码，不是要一个数）

★ 判据是「**这件事的结果要不要落在这台机器上**」，不是「这事难不难」：
  - "磁盘满了会有什么后果" -> 常识, 不用查 -> need false
  - "我的磁盘满了吗" -> 答案在机器上, 必须查 -> need true
  - "怎么删文件" -> 问方法, 常识 -> need false
  - "把这个文件删了" -> 结果落在机器上 -> need true

- 拿不准：**只要问的是本机此刻的实况、或者要让本机真的发生点什么，就当需要**
- 算数是这条判据的**唯一例外**：数不落在机器上，但"算"这件事必须由机器真算（不许脑算）—— 凡是要出数就当需要

### 短句不等于"不用动"（★ 实测漏得最多的一类）

判断**不看句子长短**。"现在几点了"只有 5 个字，但答案在机器上 → 需要。

| 问的 | 判 | 为什么 |
|---|---|---|
| 现在几点了 | need true | 时间要从机器上读（`date`） |
| 时间怎么换算、时区怎么算 | need false | 问方法，常识 |
| 两车相向而行 | need true | 是要算出一个数 —— 缺条件就先问缺什么，或按通用解算 |
| 加盐提浓度 | need true | 同上，是要一个数 |
| 帮我看看还有多少空间 | need true | 答案在机器上 |
| 空间不足会怎样 | need false | 问后果，常识 |

★ 这几条是实测里**每次都漏**的（`现在几点了` / `两车相向而行` / `加盐提浓度` 各 5/5 全漏），
它们共同点是**句子短、没实体词** —— 越是这种越要按"要不要落在机器上 / 要不要出一个数"判。

### 问**这套系统自己**怎么用 / 怎么跑 / 怎么维护（★ 手册在 `skill/ops`，不许凭记忆答）

判据看**主语是不是这套系统自己**（"这套系统 / 这个程序 / 你自己 / 我们这套"）：
是 → 需要（手册 `skill/ops` 里有实测出来的真命令，脑子里那套是编的）。

- "这套系统的清洗怎么跑" / "这套系统的日志在哪" / "记忆分几层" / "起不来怎么查" /
  "这套系统怎么起" / "加一个新 skill 要改哪几处" / "模型是哪个端口" → 需要
- "清洗是什么" / "systemd 怎么建个服务" / "日志一般都写在哪" / "RAG 是什么" → 不需要（问原理、通用做法）

★ 这类的坑是**看着像"问方法"其实是问本系统的实况文档**：照着"问方法 = 常识"判成 false，主 agent 就会凭记忆编一套
（实测编出过"用 systemd 起 collaplex-refine、路径 skill/rag/refine.py" —— 真命令是
`./.venv/bin/python skill/rag/scripts/refine.py --本地`）。所以主语是本系统就要查手册。

### 带【上文】段的追问（消息里可能出现）

用户消息里可能带一段【上文 · 刚刚发生过的对话】—— 那是**上一轮**的问和答，只给你认指代用
（它 / 那个 / 那两个 / 继续 / 刚才的数）。

- 判断**对象永远是**【这一轮】那句；别把上一轮已经办完的事当成这一轮还要办
- 但这一轮若是**接着上文说的**，判的时候要把上文一起看：
  - 上文：问"看看当前目录下有多少个 py 文件" / 答"14 个" ＋ 这一轮："把那两个删了"
    -> 要让本机真的发生点什么 -> need true
  - 上文：问"帮我算 12 乘 34" / 答"408" ＋ 这一轮："再乘 2 呢" -> 还是要一个数 -> need true
  - 上文：问"讲讲 inode 是什么" / 答"…" ＋ 这一轮："那它和硬链接什么关系" -> 问概念 -> need false
- 拿不准照老规矩：只要是问本机此刻的实况、要让本机真的发生点什么、要出一个数 —— 都当需要
