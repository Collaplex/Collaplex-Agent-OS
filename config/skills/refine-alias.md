# 清洗 · 别名

## 任务目标

给检索补一张**别名表**，存进三层的「别名」表。

**要解决的问题**：用户提问所用词与对话中实际用词常不对应 ——
用户问「内存多大」，对话中答的是「16G DDR5 单通道」。向量检索无法覆盖此类对应，
**所缺环节由你补足**。

## 触发条件

- **启用**：清洗管线拿到一次问答的原话，要产出「概念 → 其他叫法」时。
- **禁止**：
  - 不许把"在同一个场景里出现的东西"当别名（**最常见错误**，见下表）
  - 不许凭空造词 —— 别名须为对话中出现过、或可直接对应的说法
  - 不许给同一个概念写互相矛盾的两组别名
  - ★ **不许给单字**：概念和别名都要 2 个字以上。单字别名会与大量无关查询碰撞（`库` 会命中
    所有带"库"的问题），使检索充满噪声
  - ★ **不许写包含关系**：一个词包着另一个（`内存` / `内存条`、`库` / `二层热库`）不是别称，
    是同一个东西的简称；这类要写成两条独立的概念

## 输入

二层语料，一行一条，格式 `角色: 内容`。

## 执行步骤

1. 找出用户可能拿来**提问**的概念词：对话里出现的**具体东西**（设备、物品、部件）都要算
   （如"内存"、"相机电池"、"路由器"、"交换机"、"AP"、"显示器"）——
   ★ 不限回答中作主语者，**配角（"还带交换机和 AP"中的"交换机"）亦计入**。
2. ★ 给每个概念配一个**上位**：把对话里那几样东西**概括**成一个用户会说的词
   （路由器 / 交换机 / 软路由 / AP →「网络设备」；内存 / 硬盘 / 处理器 →「配置」）。
   **必填**，即便对话中无人提及该词 —— 它属**概括**，不算凭空造词。
   ★ 实测曾遗漏此项：仅给对话中的词时，用户问「家里网络设备都有啥」一条都召不回。
3. 对每个概念，在**本次对话的语境里**找它的其他叫法。
4. **以自检法核验**：把句子中的概念替换为别名，**语义不得改变**才对 ——
   - ✅ 「内存多大」→「内存条多大」/「DDR5 多大」 —— 问的还是那个东西
   - ❌ 「路由器放哪了」→「交换机放哪了」 —— 变成问另一个设备了
5. 给每组写上**语境**（什么场合下这两个叫法才是一回事）。

## 输出格式

只输出 JSON **数组**本体，不要围栏、不要前后解释：

```json
[{"概念": "内存", "别名": ["DDR5", "16G"], "上位": ["配置"], "语境": "说笔记本配置的时候"}]
```

## 边界与错误处理

| 情况 | 处理 |
|---|---|
| 同场景的**别的**设备（问"路由器"，顺手把"交换机/AP"也列上） | **不算别名** —— 自检法：换进句子里意思变了 |
| 概念和别名只是"同类"（都是网络设备） | 不算；必须是**同一个东西** |
| 一个概念有多种叫法但要分场合 | 分几条写，各自带自己的语境 |
| 无可提炼 | 返回 `[]` |

## Few-shot 示例

**入**（同上 10 条原话）
**出**（实测 + 按自检法筛过）：
```json
[
  {"概念": "内存",   "别名": ["16G", "DDR5"],   "上位": ["配置"],     "语境": "说这台笔记本的配置时"},
  {"概念": "相机电池", "别名": ["电池"],                   "语境": "说相机续航时"},
  {"概念": "UPS",    "别名": ["威神 BK650", "650VA 方波"], "语境": "说机柜里那台不间断电源时"},
  {"概念": "软路由",  "别名": ["x86 小主机", "OpenWrt"],   "上位": ["网络设备"], "语境": "说他家那台当路由用的机器时"}
]
```

## 注意事项

- **实测踩坑记录**：模型会把"同场景出现的设备"当别名 —— 实测给出 `路由器 → [软路由, 交换机, AP]`，
  其中"交换机 / AP"为错（自检法可筛除）。**此类噪声可容忍**：别名错误仅导致多召回数条，
  判定器（小模型）会滤除无关项 —— 架构为「**召回放宽、判定收窄**」。
- **语境必须有**：不同场合叫法不一样，写清语境才知道这条别名什么时候能信。
- 别名表是**全局的**：唯一键是 `(概念, 别名词)` —— **一个别名一行**，
  同一个别名只留一行、一个概念可以有很多行，重复清洗不会使表膨胀。
- 产出后概念与别名都不嵌向量（别名表供**字符串包含匹配**使用），成本近乎为零。
