# 清洗 · 概述

## 任务目标

给**一次问答**写一句总览，存进三层的「概述」条目（一次问答一条）。
其用途是**粗粒度入口**：主模型问"我们之前聊过什么"这类问题时，以其作答，无需回溯原文。

## 触发条件

- **启用**：清洗管线拿到一次问答的全部原话（二层语料），要产出这次的总览时。
- **禁止**：
  - 不许复述每条内容（那不是概述，是流水账）
  - 不许评价、发挥、补常识，只概括"谈了什么"
  - 不许跨问答（一次调用只写一次问答的概述）

## 输入

二层语料，一行一条，格式 `角色: 内容`（用户 / 助手 / 系统 / 工具）。

```
用户: 路由器放哪里了, 家里找不着
助手: 路由器在客厅电视柜下面, 挨着光猫
...
```

## 执行步骤

1. 读全部原话，看清这次覆盖了哪几件事。
2. 用一句话把它们列出来（**用对话里出现过的词**）。

## 输出格式

只输出 JSON 本体，不要围栏、不要前后解释：

```json
{"概述": "一句话, 不超过 80 字"}
```

## 边界与错误处理

| 情况 | 处理 |
|---|---|
| 只有一两句寒暄 | 照样写一句（如「只是打了个招呼」），不得返回空 |
| 内容很长、事情很多 | 择要并列，宁可略去细节，也不得超过 80 字 |
| 原话里有指代不明的"那个" | 照原话写，不得推测（猜错比含糊更糟） |

## Few-shot 示例

**入**（实测样本，10 条原话共 236 字）：
```
用户: 路由器放哪里了, 家里找不着
助手: 路由器在客厅电视柜下面, 挨着光猫
用户: 相机电池还有电吗
助手: 相机电池上周充过, 大概还能拍两小时
用户: 笔记本的内存是多少
助手: 笔记本是一条 16G DDR5 单通道, B 槽空着
用户: 机柜里的 UPS 是什么型号
助手: UPS 是威神 BK650, 650VA 方波, 带交换机和 AP
用户: 软路由什么配置
助手: 软路由是 x86 小主机, Celeron N2840 双核, 跑 OpenWrt
```
**出**：
```json
{"概述": "询问路由器位置、相机电池电量、笔记本内存、机柜UPS型号及软路由配置"}
```

## 注意事项

- 实测（旧项目，temperature=0）：236 字输入 → 概述输出，**~100 token、1~2 秒**。
- 概述须**可被检索**：写完后程序会把它嵌进向量库（三层的「概述」条目），因此不得写得过于抽象。
- 一次问答只有一条概述 —— 重复清洗时按来源**先删后插**，不会堆积。
