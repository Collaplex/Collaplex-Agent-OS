配套图：`diagrams/看图skill.drawio`（3 页）
对标：`diagrams/联网搜索skill-架构.md`（同规格）

## 0. 一句话定位

| | 管什么 | 数据面 |
|---|---|---|
| `rag` | **自家**的事（项目代码 / 配置 / 语料） | `rag_chunks` 冷库 + 二层热库 |
| `search` | **外面**的事（页面上写的字） | `search_hot` + `search_corpus` |
| `vision` | **图**（一张本地图片 → 文字） | **不留库** |

**接的是 search 留在那儿的一节**：联网搜索 §1 有支路「`汇总 --图片--> 返回结果`（直接回）」，§4 又写
「抓到了但清洗后没内容 → **只回截图**」。图能回到手上，但**全项目没有一处会读它** ——
`search` 的 SKILL.md 只能"把 `shot_path` 给出去"，交给谁？这一节就是 `vision`。

分界写进两家 SKILL.md：**页面上写的字**找 `search`，**图里画的东西**找 `vision`。

### 两条硬约束（定调，不是参数）

1. **图只在要用的时候看一眼** —— 不预读、不批量读、不因为"顺手"去读。`search` 取回来一张截图，
   **不自动**触发读图；要不要看，由当时那件事决定。
2. **图不寄存** —— 不进会话历史、不进任何库、不落第二份。那一次请求发出去，回来的是**文字**；
   图还在它原本躺着的盘上，哪儿也没多。

> 为什么这样定：上下文是**子 agent** 的活，图这种大块的东西一旦进去就洗不干净（噪声税）。
> `vision` 只做一件事 —— 替当时那件事**看一眼**，把看到的写成字交出去。

## 1. 主链（5 步）

| # | 步骤 | 输入 | 输出 | 失败怎么办 |
|---|---|---|---|---|
| 1 | 命令路由 | 命令 | 分派到「看图 / 状态」 | 命令不认识 → 回用法 |
| 2 | 拿图 | 本地图片路径 | 字节 ＋ 后缀 ＋ 大小 | 不在 / 太大 / 后缀不认 → 一句人话 |
| 3 | **看一眼（主路）** | 字节 ＋ 问句 | 文字 | 报错 / 超时 / 空 → 走第 4 步 |
| 4 | **看一眼（兜底）** | 同上 | 文字 | 两条都不通 → 照实说哪条不通 |
| 5 | 交出去 | 文字 | stdout ＋ 落盘一行账 | — |

第 3、4 步里那张图**只活在这一次请求里**：base64 进请求体，发出去，回来文字，图就散了。
没有第 6 步"存起来"，这是刻意的。

**单次一张图**（"看一眼"就是一眼）。要看好几张就发几条命令。

## 2. 两条路（主路 / 兜底）

| | 走谁 | 凭据 | 现状 |
|---|---|---|---|
| **主路** | 云端视觉 | `.env` 的 `OPENAI_*`（现在 `mimo-v2.6-flash`） | ★实测能读图（认出了截图是浙工院官网首页） |
| **兜底** | 本地 `8790` 的 `qwen3-vl-8b` | 无（`local`） | ★起它必须带 `--mmproj`，还得配 `--no-mmproj-offload`（权重+KV 已占 7271/8151 MiB，只剩 ~880M，塞不下 1.16G 的 F16 视觉塔）—— 视觉塔放 CPU 算，实测 **38.2s/张** |

**判定顺序**：主路试一次 → 不成（报错 / 超时 / 回来是空的）→ 兜底试一次 → 两条都不成，照实报。

- **谁读的必须说出来**（`by: 云端 / 本地`）—— 不然出了错分不清是哪条路的账
- **不重试、不静默**：拿不到内容就是拿不到，**绝不编一段"图里大概写着…"糊过去**
- 兜底不是"另一条更便宜的路"：它是**主路挂了才走**的。主路好的时候不切，省得两套答案打架

## 3. 参数（先定的档，改哪个说哪个）

| 项 | 值 | 为什么 |
|---|---|---|
| 单图大小上限 | `8MB` | 比 search 的单页 5MB 松一点（截图本来就大），但不能没闸 |
| 允许后缀 | `.jpg .jpeg .png .webp .gif .bmp` | 视觉模型认的就这几样 |
| 单轮次数上限 | `100` 次 | 防发疯；跟 search 一个档（2026-10-09 老板定：单次对话上限 100） |
| `max_tokens` | `1024` | 描述一张图够了；太小会被思考吃光 |
| 超时 | `180` 秒 | 跟外援同档 |
| 落盘 | `logs/vision/` | 每次调用一行账（谁读的 / 耗时 / 图多大）＋产出 `.md` |

**闸放程序侧**（命令路由那一关硬拦）—— 跟 search 同款：挂 skill.md 侧是软约束，拦不住发疯。

## 5. 加一个 skill 要做的三步（没有注册表）

1. **建命令库索引**：`.venv/bin/python skill/vision/scripts/retrieve.py index`
2. **重扫 skill 索引**：`.venv/bin/python skill/skill_search/main.py index`（扫各 `SKILL.md` frontmatter）
3. **自检的清单加它**：`selfcheck.py` 那行 `wanted = (...)` 加上 `"vision"`

外加一处**前置改动**：`start_models.sh` 主模型那行加 `--mmproj`（`mmproj-Qwen3-VL-8B-Instruct-F16.gguf`
1.16G 已在盘上）—— 不加的话第 2 节的兜底必报 `image input is not supported`，等于兜底是假的。

## 7. 实测记录（2026-10-09）

| 项 | 实测 |
|---|---|
| V1 主路 | ✅ 拿 `search` 抓的浙工院首页截图问"标题是什么" → 答 `明德敬业 知行合一`（1.8s · `mimo-v2.6-flash`） |
| V2 兜底 | ✅ 补了 `--mmproj --no-mmproj-offload` 之后本地也读得出来：同一张图答对校训，**38.2s/张**（视觉塔算在 CPU 上） |
| V3 兜底没带 mmproj | ✅ 原话：`HTTP 500 image input is not supported - hint: … you may need to provide the mmproj` —— **不静默当成功** |
| V4 图不在 / 后缀不认 / 超上限 | ✅ 三条都是一句人话 ＋ 退出码 1：`图片不在: …` / `这个后缀不认: .txt (认这些: …)` / `图太大了: 8.6MB (上限 8MB)` |
| V5 两条都不通 | ✅ 本地还在装权重时真触发过：`两条路都不通 —— 图里有什么, 我不知道 (绝不编)` ＋ 逐条列出两条路各自的错 |
| V6 空图 / 纯色 | ✅ 全白图 → `图上没有文字，整张图是空白的（纯白色）`；纯色图 → 报出颜色。**都没硬凑** |
| 闸到顶 | ✅ 把状态摆到上限：`这一轮已经看了 20 张图, 到上限 20 就停 —— 这是防钻牛角尖的闸。…`，退出码 2 |
| V7 回归 | ✅ 自检 **24/24**；pyright 整仓 **0 errors / 0 warnings / 0 informations**；`rag` 检索不受影响 |
| V8 命令库能被检索到 | ✅ 命令库索引 **2 条**（`看图` / `状态`）；skill 索引重扫 **10 条**（vision 带着 `trigger_keywords` 进去了） |
| 纯逻辑自检 | ✅ `skill/vision/tests/看图_check.py` **15/15**（查图三拦 · 单轮闸 4 条 · 端点拼装 · 小图合法性）—— 不花模型钱 |

**跑真 agent 四轮**（`tests/vision_rounds_probe.py`）：R1 该看（主 agent 自己走 `看图`）·
R2 顺着 `search` 的截图看 · R3 一道算数（验路由不串）· R4 给一张不存在的图（验照实说）。

**两个坑（已固化进代码/脚本）**

1. `import core` 会跟 `skill/skill_search/scripts/core.py` **撞名** —— pyright 解析到另一边，报 **121 条假错**。
   公共件改名 `vision_core.py`；同理 `status.py` 这种通用名别在测试里 `import`（会撞 outsource / mtp 的 `status.py`），
   所以 1x1 小图挪进了公共件。
2. 兜底那条**光有端点不算数**：端点答 200 只证明"服务活着"，不证明"能读图"。
   要判能不能读图，必须真送一张图 —— `状态 --真读` 就是干这个的。
