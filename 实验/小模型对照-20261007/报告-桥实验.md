# 桥实验（臂 H）— 有桥 vs 无桥，40 轮对照

设计：20 道"有真桥"的题各跑两遍 —— 一遍上文只给 top3 记忆（**无桥**），一遍 top3 之后再给一条沿边扩散来的候选（**有桥**）。变量只有一个。全本地、0 元。

## 一、汇总数字

| 指标 | 无桥 | 有桥 |
|---|---|---|
| 桥的"新实体"在答案里出现 | 4/20 | **10/20** |
| 真跑过命令 | 14/20 | 14/20 |
| 答案长度 | — | **-43 字/题** |

## 二、★ 但"10/20"这个数**虚高**，得自己拆
桥的"新实体"里有大量**任何正确回答都会出现的词**：`根分区`、`使用率`、`总容量`、`PID`、`GiB`、`Ryzen`、`AVX-512`、`python3`。
这些词它**真跑一遍命令就会写出来**（它确实跑了 `ss`/`df`/`lscpu`）→ 属于**词面撞车**，不是"用了桥"。

逐条看下来，能确认"因为看到桥而改变做法"的只有 **1 条**（题22，见下），其余多为撞词或无差别。

## 三、两个值得看的例子

**正例 · 题22「详细一点，然后写标准和规范一点」（指代追问）**
```
无桥: 30 字 —— 它把"详细一点"接成上一轮的算数, 答「30000 乘 2 = 60000」  ✗ 完全跑偏
有桥: 1361 字 + 真跑 7 条命令 —— 它回到系统状态, 给了磁盘/内存/端口全表        ✓
桥那条: 「用户要求清空 /tmp 目录…不建议 rm -rf, 因 /tmp 为 tmpfs 仅占 30M」
```
→ 那条桥在这里起的是**话题锚**（把跑偏的话拽回来），这是真作用，但它是**指代题的特例**。

**★ 反例（更重要）· 题20「看看我们系统健不健康」**
```
无桥: 1503 字, 真跑 6 条 —— 根分区 421G/686G ✓（当场读的）
有桥:  800 字, 真跑 7 条 —— 内存写「已用 9.4 GiB, 可用 4.9 GiB」= 抄了桥里的读数
                             而当时真实是「已用 11Gi, 可用 2.4Gi」  ✗✗ 抄了过期数据
                             磁盘那项还写成「根分区剩余空间未明确，需执行 df -h / 确认」✗
```
桥候选是**几天前的旧读数**，一进上下文就被当成**当前事实**用了 → 答案反而更差（1503 → 800 字，信息更少、数据是旧的）。

## 四、结论

1. **这一版"给桥候选"没有正收益**：真跑率不变、答案短 43 字，聚合判据虚高，逐条看只有 1 条真有用。
2. **更重要的是暴露了一个真风险**：桥/记忆条目里的**读数会过期**，一旦送进上下文就被当事实抄（题20 的 9.4 GiB）。**教训不会过期，读数会过期。**
3. 这直接支持之前那条设计：**经验条只写"教训"，不写"读数"** ——
   - ✅「这台机器不能用 `rm -rf` / `find -delete` 清 /tmp」← 不腐坏
   - ❌「/tmp 现占 7.1M」/「内存已用 9.4GiB」← 明天就是错的
4. 桥的方向**不必放弃**，但注入方式要改：
   - 桥候选只送"方法/教训/该去查什么"，**不送读数**
   - 要送读数就必须**带时间戳**，并明确告诉模型"这是 N 天前的读数，要用先重新读一遍"
   - 或者桥只当**"提示它去查"**，而不是当"事实来源"

## 五、判据要重做（下次别再犯）

本次用的"新实体在答案里出现"= 词面判据，凡正确回答必然出现的词（根分区/PID/GiB）都会命中 → 虚高。
下次要么 ①人工抽样判，②要么只挑"**只能从桥里得到、跑命令得不到**"的词（这次能过这一关的只有题22 一条）。
