# 习惯模型：把"该动手 / 不该动手"当**训练目标**训出来

老板定的方向："这个靠提示词应该没什么大用，这个是目前模型训练的遗留问题，
所以正确的路还是去搞模型架构设计加训练让模型能在我们 8g 卡上跑出好效果。"

这份报告是对应他新架构图 `diagrams/模型架构设计.drawio` 里**「习惯模型」**那一件的第一次实测。

## 做法（8G 卡友好、0 元、不碰显存）
1. **基座冻结**：Qwen3-0.6B（魔搭下的 safetensors，1.5G）只当特征提取器
2. **CPU 提特征**：59 道题各取最后一层 hidden 平均池化（1024 维）→ 缓存 `习惯模型-特征.npz`（**7 秒**）
3. **训窄头**：手写逻辑回归（1024 → 1，**1025 个数**），**留一交叉验证**
4. 全程 CPU，那只占着显存的 llama-server **一个字都没动**

## 结果

| 臂 | 准确率 | 该动没动（最重的错）| 不该动却动 |
|---|---|---|---|
| ① 现有模型实际判断（8B／云端，从 `样本.jsonl` 反推）| 49/59 = **83.1%** | **7 题** [19,38,39,42,43,44,45] | 3 题 |
| ② 多数类基线（全答"该动"）| 35/59 = 59.3% | 0 | 24 |
| ③ **训练窄头**（0.6B 隐层 + 逻辑回归）| 52/59 = **88.1%** | 6 题 | **1 题** |
| ④ **合并（任一个对就对）** | 56/59 = **94.9%** | — | — |

### 逐题对照（④ 互补性）
- 都对 45 题　只现有模型对 **4** 题 [1,2,20,21]　只窄头对 **7** 题 [19,22,29,38,39,45,49]
- ★ 两个都错 **只剩 3 题** [42,43,44] ⇒ 合并上限 **94.9%**

## 三条结论

### 1. ★ 习惯能当训练目标训出来，而且**跟脑子大小无关**
**1025 个数的窄头（88.1%）> 8B 通用模型（83.1%）**。
差的不是参数量的多少，是**有没有拿我们自己的数据训过** —— 老板这句话被实测证实。
而且这个件**小到显存可以忽略**，完全符合"8G 卡跑出好效果"。

### 2. ★ 多个件是**互补**的，不是重复的
窄头救回现有模型漏的 7 题（19/22/29/38/39/45/49），现有模型救回窄头漏的 4 题（1/2/20/21）
⇒ **合并 94.9%（+6.8 点）** ⇒ 架构图上画"多个件协同"是有据的。

### 3. ★ 剩下的 3 题暴露了下一件该干什么
[42,43,44] 全是**「算数」层**：骰子表达式期望 / 三管齐开注水 / 两车相向而行。
**题面看着像常识问答，实际要出一个数** ⇒ 现有模型和窄头**都**判成"不用动"。
- 这类在题库里只有 **3 条** ⇒ 训练数据不够，学不出来
- 而且**提示词也治不了**：这三题正是我改 `judge.md`（"短句不等于不用动"）时列的那一类（5/5 全漏）
⇒ **单靠"题面 → 该不该动"的分类有天花板**；下一步要么补这类样本，要么按图上的**门控模型 + 循环**（先看一眼再决定）。

## 窄头学到的到底是什么（看它救回来的题）
| 题 | 该动手 | 现有模型 | 窄头 |
|---|---|---|---|
| 看看现在几点了 / 现在几点了 | 要动 | 漏 ✗ | 对 ✓ |
| 加盐提浓度 | 要动 | 漏 ✗ | 对 ✓ |
| 把这句话翻译成英文 | 不用动 | 瞎动 ✗ | 对 ✓ |
| 详细一点，然后写标准和规范一点 | 不用动 | 瞎动 ✗ | 对 ✓ |
| 用 markdown 给我一份短文…… | 不用动 | 瞎动 ✗ | 对 ✓ |

⇒ 它学到的正是**习惯**（"要不要落在机器上 / 要不要出一个数"），
而这些**提示词反复改也治不好**。

## 判据纪律（这轮踩到的）
- ★ **不能用"总准确率"当判据**：全答"该动"能刷到 59.3% 且 0 漏，但那是**最蠢**的模型（24 题瞎动）。
  ⇒ 必须同时看 **该动没动**（漏）和 **不该动却动**（瞎动）。
- 59 条样本、留一验证 ⇒ 1 题 = 1.7%，置信区间很宽（±8% 量级），**别把 88.1% 当精确值**。
- 特征只有 mean-pool ⇒ 粗，但够用。
