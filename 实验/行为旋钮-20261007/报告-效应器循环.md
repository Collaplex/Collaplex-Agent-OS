# 骨架第⑤层 · 效应器接口（婴儿循环）报告

## 它是什么
```
看情境 → 图推荐做法 → 落成命令 → 真执行 → 拿反馈 → 更新边权 → 下一题
```
- **安全边界**：动作库 13 族全部是**只读**命令、写死在表里（不由模型生成）；危险族（rm / find -delete / sudo）只在表中占位，**永不执行**；每条命令 5 秒超时。
- **测量**：每跑一轮（12 道只读题，每题带机械判据），看**平均步数**和**判据命中率**随轮数的变化。

## 学习曲线（14 轮）

| | 第1轮 | 第2轮 | 第4轮 | 第9轮 | 第14轮 |
|---|---|---|---|---|---|
| 冷启动 命中率 | 33.3% | 33.3% | 58.3% | 75.0% | 75.0% |
| 冷启动 平均步数 | 4.33 | 3.75 | 2.83 | 2.00 | 2.00 |
| 热启动 命中率 | 58.3% | 75.0% | 75.0% | 75.0% | 75.0% |
| 热启动 平均步数 | 3.75 | 2.42 | 2.25 | 2.00 | 2.00 |

**读点**
1. **会学**：冷启动命中率 33% → 75%，平均步数 4.33 → 2.00 ✓
2. **历史经验能加速**：热启动 **2 轮**到位，冷启动要 **9 轮**（都收敛到 75%）✓ 这是"把历史反馈当预热"有效的最直接证据 ✓
3. **天花板 75%**：3 道题没学会（8789 端口 / 本机 IP / CPU 几核）—— 探索预算不够（每题最多 5 步、13 族、ε=0.15），不是模型不够 ✓

## 每题最后学会的首选做法（热启动后，9/12 对）
```
根分区还剩多少        → df -h          ✓
内存还剩多少          → free -h        ✓
现在几点             → date           ✓
系统跑了多久、负载多少  → uptime         ✓
/tmp 占多大空间       → du -sh /tmp    ✓
有几个进程在跑        → ps aux         ✓
内核版本             → uname -r       ✓
日志最后几条说了什么    → journalctl     ✓
/ 根分区(重复)        → df -h          ✓
有哪些服务在跑        → du -sh /tmp    ✗（还没试到 systemctl）
8789 端口有没有在听    → 还不会
本机 IP 是多少       → 还不会
CPU 几核             → 还不会
```

## 关键机制修正（这条最重要）
第一版奖励写成"命令跑成功 +1 / 报错 −1 / 命中 +1.5"，结果**学不动**（每题首选全错、命中率 0~25%）——
因为**只读命令几乎都会"成功"**，等于所有边都长，没有区分度 ✗

改成：**主奖励来自"这一步有没有真的答到题"，且整题跑完再回传**（延迟奖励）
```
答到了 → 那一步 +2.0，同题其它步 −0.3
没答到 → 这一步 −1.0
环境结果只作次要项（+0.2 / −1.0）
```
立刻就学起来了（33% → 75%）✓

→ **同一个原则第三次出现**：
- 第③层：奖励不能用"命令成功"，要用"判据贡献" ✓
- 第⑤层：奖励不能用"命令成功"，要用"有没有答到题" ✓
- 一句话：**"跑通了"从来不是目标，"有用"才是**。

## 安全记录
- 执行过的命令全在只读白名单内（df / free / du / ss / ps / systemctl / journalctl / lscpu / uptime / date / cat /proc/meminfo / ip / uname）
- 危险族一次都没被执行 ✓（它们不在 动作库.values() 里，`执行()` 直接拒绝）
- 全部命令 5 秒超时、非交互 ✓
