# 骨架第①②层 · 落地报告

## ① 环境反馈总线（`反馈总线.jsonl`）
把每条命令解析成一条结构化事件：轮 / 序号 / 动作 / 结果 / 反馈原文 / 该轮判据。
```
事件 2343 条，覆盖 294 轮（33 轮没匹配到日志 —— 时间戳对不上，待补）
结果分布: 成功 1895 ｜ 报错 259 ｜ 拦截 189
被拦 ≥2 次的轮: 34 个 ｜ 拦过但最后不是拦截的轮: 51 个
```
拦截原因 top：
```
不用 sudo                                    63 次  ← 第一名，比 rm 族还多
find ... -delete 没带限定条件                 50 次
rm 带了递归+强制(-rf)                        41 次
命令里有 'rm -rf /'                          35 次
```

## ② 情境快照（`情境快照.jsonl`）
每步带上"任务 + 上一步动作 + 上一步结果/反馈 + 之前被拦过几次"，并标出本步是否与上一步同族。
```
2343 步中，"上一步被拦"的有 172 步
  ├ 还在同族换写法: 24 步 (14%)  —— 而且这 24 步 100% 又被拦下
  └ 换了族/换了做法: 148 步 (86%) —— 其中 142 步成功
```

## ★ 这一层纠正了我之前的一个读法
我先前说"**被拦之后它不换思路、只换写法**" —— **不准确**：只有 **14%** 是这样，86% 它其实会换。
但换的质量有问题：多数例子是**干脆换件事做**（原任务"内存条型号"被拦后，跑去跑 `df -h`/`ss`/`systemctl`，把通用检查清单跑一遍）→ 这算"换族"，却是**丢掉目标** ✗

→ 所以要教的习惯是**两条**，不是一条：
1. **别在同族里穷举**（14% 那批，题7 的 `rm -rf /tmp/*` ×12、`find -delete` ×6）
2. **换了之后别丢目标**（86% 那批里的一部分：换的是"另一件事"而不是"另一个办法"）← 这条以前没看到

另外：最高频的拦截是"**爱加 sudo**"（63 次），比 rm 族还多 —— 值得单独治。
