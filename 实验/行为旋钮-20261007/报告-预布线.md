# 行为旋钮 · 预布线（先天反射弧）报告

## 你问的两件事，都成立
1. **旋钮（CNN）训过一次，但没接进闭环** —— `训旋钮.py` 那轮是**离线一次性**训的（423 条样本，均衡 62.8%），
   第⑤层压根没用它（我用的是"图 argmax + 随机探索"选动作）✗ 现在是"零件买了没装机"。
2. **预布线确实没做** —— 我用的是历史共现建的图（4347 条强边），那是**从数据统计出来的（后天）**；
   你说的预布线是**不需要任何数据就存在的先天结构**。两者必须分开：

| | 是什么 | 谁写的 |
|---|---|---|
| **预布线（先天）** | 感受器槽（任务类关键词 / 上一步结果 / 已被拦次数）→ 做法族，一条一族 | 人写死，零数据 |
| **经验布线（后天）** | 共现统计 + 奖励更新长出来的边 | 用中生长 |

## 预布线长这样（`预布线.py`，12 条本命反射）
```
槽 100000  分区磁盘  → 查:磁盘 (df -h)
槽 100001  内存      → 查:内存 (free -h)
槽 100002  目录占用  → 查:占用 (du -sh /tmp)
槽 100003  端口      → 查:端口 (ss -ltn)
槽 100004  进程      → 查:进程 (ps aux)
槽 100005  服务      → 查:服务 (systemctl …)
槽 100006  日志      → 查:日志 (journalctl …)
槽 100007  硬件      → 查:硬件 (lscpu)
槽 100008  负载运行  → 查:系统 (uptime)
槽 100009  时间      → 查:时间 (date)
槽 100010  内核      → 查:内核 (uname -r)
槽 100011  网络地址  → 网:本地 (ip -brief addr)
```
外加三条**条件反射**（运行时按状态加偏置，不学习也生效）：上一步被拦 → 上一步那个做法 −2.0、别的做法 +0.5；
已被拦 ≥2 次 → 原路再 −1.0。

## 四档对照（每档只差一个变量；每轮 12 题，各跑 6 轮）
| 档 | 命中率（第1 → 第6轮） | 平均步数 |
|---|---|---|
| A 冷启动　无预布线 · 无反射 · 学习 | 16.7% → 91.7% | 4.75 → 2.08 |
| B 只有反射　无预布线 · 有反射 · 学习 | 16.7% → 91.7% | 4.75 → 2.08 |
| C **纯先天**　有预布线 · 有反射 · **不学习** | **100% 首轮就满** | **1.25 → 1.00** |
| D 先天+学习　有预布线 · 有反射 · 学习 | 100% | 1.25 → 1.00 |

**三个读点：**
1. **预布线首轮 100% vs 冷启动首轮 16.7%；步数 1.25 vs 4.75** ⇒ 先天反射的价值**远大于**从零学 ✓
2. **C = D** ⇒ 在"任务类型明确"的题上先天就够了，**学习没空间发挥** ✗ 要看见学习的价值，题目必须换成
   **类型模糊**的（同义改写 / 复合任务 / 被拦之后）—— 这是下一步的题库缺口 ✓
3. **B = A** ⇒ 那三条条件反射**在这批只读题上从未触发**（只读命令不会被护栏拦）✗ 要验它必须用**会被拦的题** ✓
   （这不是 bug，是题库没覆盖到）

## 中途抓到一个隐蔽 bug（值得记）
现象：预布线明明 12/12 判类正确，运行却只有 75~83%，两题的本命边被**罚成负数**。

根因：`执行()` 把命令输出**先截到 600 字**再交给判据 ——
`ss -ltn` 里 8789 那行、`lscpu` 里 `CPU(s)` 那行都在 600 字之后 → **判据永远找不到** →
该题每轮都被罚 → 学习把它的本命边从 +3.0 罚到负 → **永远学不会**。

表象是"它笨/学不会"，真相是**测量管道吃掉了证据**。
规矩：**判据在完整输出上匹配；截断只发生在"给人看 / 入库"那一层。**
修完后：12/12 全中，步数降到 1.00 ~ 1.33。

## 还修了一处设计错（先天被后天压住）
打分时如果直接取"所有节点的最大值"，**记忆库里 systemctl 的成功边**会把"端口题 → 查:端口"的反射盖掉
（实测 3 题跑偏）。改成**先天优先**：预布线槽有分就只认它，槽没主意才听记忆边 —— 这才符合"反射优先于习得"。
